# LittleCrawler 工程化评估

## 当前实现与技术栈

LittleCrawler 是一个异步多平台爬虫应用，目前实际支持小红书和知乎。

- CLI 入口：`main.py`，通过 Typer 解析参数并由 `CrawlerFactory` 创建平台爬虫。
- 爬虫核心：`src/platforms/`，使用 Playwright、CDP 和 HTTPX 完成登录、签名与数据请求。
- 数据存储：CSV、JSON、Excel、SQLite、MySQL、MongoDB。
- 基础服务：Redis/内存缓存、代理 IP 池、异步文件写入和词云生成。
- Web 后端：FastAPI；`CrawlerManager` 通过子进程启动 CLI 并转发日志。
- Web 前端：Next.js 14、React 18、NextUI、Tailwind CSS。

主调用链如下：

```text
CLI / FastAPI
    -> CrawlerFactory
    -> XHS / Zhihu crawler
    -> HTTP client + Playwright/CDP
    -> platform storage factory
    -> file / SQL / MongoDB
```

## 本次已经落地

- Python 版本统一为 3.12，并使用 `.python-version` 固定开发解释器。
- 以 `pyproject.toml` 和 `uv.lock` 作为依赖唯一来源。
- `requirements.txt` 改为 UV 自动导出的旧部署兼容文件。
- 运行依赖与开发依赖分组；增加 Ruff、mypy、pytest 和 pre-commit。
- 建立渐进式格式化基线：新改动的 Python 文件使用 Ruff format，暂不对历史代码做全仓格式化。
- 增加 GitHub Actions，在 Python 3.12 下执行锁定安装、Ruff、mypy 和 pytest。
- 修复 Web API 传入 `--max_page` 但 CLI 不识别的问题。
- 修复知乎 detail/creator 参数没有映射到知乎配置的问题。
- 移除尚未实现的 xhy 爬虫选项，避免选择后运行时报错。
- 修复知乎 MongoDB 内容使用错误 `note_id` 键的问题。
- 修复小红书 CSV/JSON 创作者数据被静默丢弃的问题。
- 恢复前端缺失的类型化 API 客户端，修复登录响应缺少用户信息的问题，并恢复严格 TypeScript 构建。
- 接通 Web 的代理/CDP 配置，修复 detail/creator 参数、数据预览格式和成功日志展示。
- 为 WebSocket 日志与状态接口增加 Token 认证。
- 将 CORS 改为环境变量 allowlist，并保护环境检查接口。
- 为上述契约与存储行为增加最小单元测试。

## 后续优化建议

### P0：安全与可用性

1. 重构默认管理员初始化。当前会自动创建公开默认账号，密码哈希也不适合作为生产密码存储；建议首次启动由环境变量注入管理员信息，并使用 Argon2 或 bcrypt。
2. 明确发布器进程模型。爬虫运行在子进程，而发布器状态保存在 API 进程内，当前无法共享浏览器会话；应设计独立 worker + IPC/RPC，或改为同进程任务托管。

### P1：数据可靠性

1. `AsyncFileWriter` 的锁属于单个实例，而存储工厂会反复创建实例；并发写同一 JSON 文件仍可能覆盖数据。建议每次爬虫任务复用单一 writer，或改为 NDJSON/原子替换。
2. JSON 存储当前每写一条都读取并重写整个文件，数据量增大后成本接近 O(n²)。建议使用 NDJSON，展示时再流式聚合。
3. 数据库的“先查后写”需要唯一约束和原子 upsert，避免并发任务插入重复数据。
4. 上传接口应限制文件大小、校验真实图片格式，并在 `finally` 中清理临时文件。

### P2：持续工程化

1. 当前 mypy 先覆盖 CLI/API 契约和测试；后续按模块消化历史类型问题，再逐步扩大 `files` 范围。
2. Ruff 首批仅启用低噪声正确性规则。全仓格式化、导入排序和更严格规则应放在独立提交，避免与功能改动混杂。
3. 前端 API 客户端和严格 TypeScript 构建已经恢复；后续建议提交前端 lockfile，并将 `npm run typecheck` 加入独立 CI 工作流。
4. 为 CLI 参数、认证、WebSocket、文件并发写入及数据库 upsert 增加集成测试。
